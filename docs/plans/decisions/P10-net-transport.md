# P10 decisions: Net transport

The questions of the [net transport plan](../2026-11-19-net-transport.md). Numbers are stable.

## Questions

| # | Question | Options | Recommendation | Answer |
|---|----------|---------|----------------|--------|
| 1 | Where P10 stops on clients | (a) P10 builds client mirrors and wires them to today's screens, so a client plays its own map; (b) P10 stops at the transport API and P11 wires the screens | **(a)**: the transport's live check needs something to play, and P11 then adds only co-op rules | **Answered November 19, 2026 (user):** as recommended |
| 2 | How a client's campaign mirror stays equal to the host's | (a) every campaign batch also sends the run's capture (`RunSaveSections`' six parts), and facts are for presentation only; (b) the mirror follows facts, and P11 adds fact kinds for battle-end gold, falls and a skipped pick | **(a)**: campaign batches are rare and small, it covers every change no fact records, and it answers design items' P11 row ("or another way to sync them") | **Answered November 19, 2026 (user):** as recommended |
| 3 | Where the run's RPCs live | (a) a new `NetRelay` autoload, registered after `CampaignService`; (b) a child node of `SteamNetwork`; (c) RPCs added to `CampaignService` | **(a)**: one home for run traffic, free of Steam, so the harness can put one under each test branch. CLAUDE.md §1 asks before a new autoload | **Answered November 19, 2026 (user):** as recommended |
| 4 | The authority gate (kit conflict) | (a) a static `NetGate.is_authoritative(api)` / `has_session(api)`, which `SteamNetwork`'s helpers call, so `NetRelay` checks its own branch's API; (b) the kit's rule as written: always `SteamNetwork.is_authoritative()` | **(a)**: still one definition (the kit's reason for the rule), and it lets two peers run in one process. Asked because CLAUDE.md says to stop when the kit and the project's code would differ | **Answered November 19, 2026 (user):** as recommended |
| 5 | The headless two-peer transport | (a) a loopback `MultiplayerPeerExtension` pair in `tests/net/`, with drop, delay and reorder switches, plus one ENet localhost case; (b) ENet localhost only | **(a)**: no ports to collide in parallel runs, and drops are scripted; the one ENet case proves Godot's real RPC path | **Answered November 19, 2026 (user):** as recommended |
| 6 | Reconnecting and rejoining | (a) a client that loses the host mid-run stays on its screen, shows the wait overlay and tries `join_lobby()` on the same lobby every 1.0 s (the kit's retry interval) until it is back or the wait ends; every rejoin loads a fresh snapshot; catch-up from memory is only for gaps inside a connection; (b) a lost client returns to the main menu and rejoins by hand; (c) as (a), but a short drop catches up from the facts kept since the checkpoint | **(a)**: one rejoin path for a cable pull and a crash, and nothing to keep valid across a reconnect | **Answered November 19, 2026 (user):** as recommended |
| 7 | What "the game pauses for everyone" stops | (a) while any seat is dropped, the host refuses every command, campaign and combat, its own included ("paused"), batches already resolved still play, and every peer shows the overlay with the time waited; (b) only the dropped player's map pauses and the other maps play on (P01 allowed this) | **(a)**: the vision says the game pauses for everyone; (b) would let a battle end around an absent player | **Answered November 19, 2026 (user):** as recommended |
| 8 | What removing a dropped player does in P10 | (a) P10 builds `remove_seat()` and `seat_removed` and tests them; the host's Remove button and its effects (the map leaves, the seat leaves the save, the run is archived as forfeited) come with P11's forfeit, which owns that save change; until then the host waits or ends the match; (b) P10 builds the whole forfeit, pulling the save change in from P11 | **(a)**: the orchestrator gives the forfeit save change to P11, and a removal without it would leave a battle that can't finish | **Answered November 19, 2026 (user):** as recommended |
| 9 | What the build check compares | (a) the game version and a computed wire-contract fingerprint; (b) as (a), plus the MD5 of every file under `res://data/` and `res://maps/`; (c) as (b), plus a build id stamped at export | **(b)**: clients mirror with their own content, and release builds send no hashes, so other content would desync silently. NT1 times the hash at boot and reports it; (c) needs export tooling that doesn't exist | **Answered November 19, 2026 (user):** as recommended |
| 10 | Choosing the route before P11's votes | (a) with P10 alone, any seat's node choice is sent and the first to arrive wins (today's rule for two seats on one floor); (b) only the host can choose until P11's votes | **(a)**: no new rule, and the live check exercises a client's campaign command; P11 replaces it with votes | **Answered November 19, 2026 (user):** as recommended |
| 11 | A dev transport for one machine | (a) ENet host and join in `SteamNetwork`, debug builds only, from command-line flags (kit's testing guide §6), so two instances play on one machine; (b) none: Steam on two machines only | **(a)**: daily multiplayer testing without a second machine or account; M4's live test still needs two machines | **Answered November 19, 2026 (user):** as recommended |
| 12 | Edits in other lanes' files | (a) Lane E makes the small edits its steps need, one step at a time, while the owning lane has no open branch on those files: `scripts/campaign/` commands and `campaign_session.gd` (Lane B), `scene_router.gd` (Lane B), `battle_controller.gd`'s send (Lane A), and EV2's `EventCommand` and `OpenEventCommand` wire forms (Lane C, or Lane C adds them when EV2 is still open); (b) each owning lane makes them as its own steps | **(a)**: each is a few lines in one method, and splitting them across lanes would sequence four lanes behind one contract | **Answered November 19, 2026 (user):** as recommended |
| 13 | The disconnect overlay's home | (a) P10's NT6 builds `SeatWaitOverlay` (its own `.tscn`, documented `@export`s, keyboard, mouse and controller), with the Remove button hidden until P11; (b) P11 builds it | **(a)**: pause and rejoin are P10's, and the live check needs to see them | **Answered November 19, 2026 (user):** as recommended |
| 14 | Desync checks in release builds | (a) state hashes travel only in debug builds, and the M4 live tests run debug exports; (b) send hashes in release builds too, after NT7 measures their cost | **(a)** for the MVP: it keeps release batches small, and debug exports cover the live tests; revisit with NT7's numbers | **Answered November 19, 2026 (user):** as recommended |
| 15 | Where the build check sits in `LobbyAdmission.decide()` (NT1) | (a) right after the version: version, build, campaign, membership; (b) last, in `Refusal` order | **(a)**: a wrong build is the more basic fault, and the version check still comes first, so a version bump shows its own text | **Answered November 19, 2026 (user):** as recommended |
| 16 | What the fingerprint's network format covers beyond the plan's list (NT1) | (a) collected: every autoload's `get_rpc_config()` (adds `SaveService`'s and `SceneRouter`'s RPCs; `NetRelay` joins by itself), every class under `res://scripts/` descending from `Command` by its `WIRE_TYPE`, and `SeatDirectory.State`; (b) the plan's list exactly, with hand-kept lists of command classes and RPC scripts | **(a)**: nothing to keep by hand, and an RPC change on any autoload breaks peers just as `SteamNetwork`'s would | **Answered November 19, 2026 (user):** as recommended |
| 17 | Exported builds' `.remap` pointers in the content digest (NT1) | (a) follow each `.remap` to the converted file and hash that under the original name; (b) hash files as listed | **(a)**: with (b) an export hashes only the pointers, so other content passes the check; an editor run and an export of one commit then differ, which the same-build rule allows | **Answered November 19, 2026 (user):** as recommended |
| 18 | `SeatDirectory`'s states in NT1 | (a) `CONNECTED = 0`, `DROPPED = 1`; NT6 appends `REMOVED = 2`, `remove_seat()` and the signals; (b) all three states now, `REMOVED` unused until NT6 | **(a)**: nothing in NT1 sets a removal, and the enum is append-only | **Answered November 19, 2026 (user):** as recommended |
